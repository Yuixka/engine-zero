Graph-level engineering checks

Body-joint network

Each candidate is a body/joint graph, not a named linkage selected from a menu. Adding an R–R–R dyad introduces two bodies and three revolute constraints while preserving the original mobility count.

Advanced research: inspect / edit the candidate graph

Exports include body IDs, local joint anchors, actuator, output point, and reproducible base / dyad parameters. Modify JSON and select Test imported graph; you may provide custom seedPoses for graphs without an available analytic initialization. The mobility count is necessary, not sufficient, for physical motion.

What counts as progress here? The engine can now change the number of links, the joint types (rotary and sliding), the placement of attachment points, and the connectivity of additional dyads; a common constraint solver tests the resulting motion. It does not autonomously invent physics, prove novelty, perform collision/force analysis, or output fabrication-safe geometry. Cross-topology invention research is established prior art, and our next milestone is benchmarked physics and manufacturing constraints.
