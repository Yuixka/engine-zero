# ENGINE ZERO v0.2 — Graph-based mechanism architecture discovery

**Research build · 15 November 2026 · Offline · No external dependencies**

Engine Zero has moved beyond a parameter-only four-bar synthesizer. It now represents **bodies, joints, drivers and outputs as a graph** and can apply a graph grammar that changes the machine's connectivity, not just dimensions. Every selected mechanism is traced across a driven rotation by the **same general planar constraint solver**.

This is a reproducible experimental research instrument, **not** an invention, CAD-certified part, dynamics engine, proof of originality, patent clearance, or equipment ready to fabricate.

## Run it

- Open `Engine_Zero_Architecture_Discovery.html` in any current browser. It includes all code and works offline, no server required.
- To work on the source, keep `index.html`, `legacy-fourbar.js`, `graph-engine.js`, and `discovery.js` in the same directory and open `index.html`.
- Run the math and regression tests from a terminal with Node 18 or newer:

  ```sh
  node test.js
  ```

The tests cover exact closure of legacy four-bar geometry, general solver recovery from an inaccurate pose, independent numerical checks of the analytic Jacobian for R and P joints, a completely user-defined one-crank mechanism, six- and eight-link graph mutations, and serialization/reconstruction.

## What is implemented

| Layer | Implementation |
|---|---|
| Mechanism graph | Arbitrary rigid-body IDs, ground body, local joint anchors, revolute and prismatic joints, driver, output point |
| Mobility filter | Generic 2D structural count: `3 × moving_bodies − 2 × (R + P joints) − 1 actuator`; zero remaining DOF required |
| General solver | Damped least-squares Newton with analytic constraint Jacobian and backtracking, continuation through the cycle and assembly branch checks |
| Primitive families | Four-bar (`4R`); slider crank (`3R1P`) |
| Construction grammar | Add two connected rigid bodies through an `R-R-R` dyad, attach its ends to two existing bodies, randomly choose anchors, vary geometry, or rewire connections; repeated to reach 6/8-link assemblies |
| Automated search | Seeded graph generation, topology changes (grow / remove / rewire dyads), numeric mutations and family-specific incumbents |
| Evaluation | Geometric full-cycle closure, sampled singularity/branch-discontinuity rejection, optimal 2D translation alignment, path RMSE plus explicit complexity penalty |
| Interface | Family champion picker, animated mechanism, connectivity view, parameter controls, source graph JSON edit/import, JSON/SVG/CSV export |

**What topology search means here:** Configurations are generated by graph rules instead of selecting only prewritten complete linkage templates. The rules themselves are still hand-programmed and explore only a narrow subset of possible machines. This is **not** autonomous discovery of previously unknown mechanisms.

## Exported graph format

```json
{
  "version": "0.2",
  "family": "custom-1R",
  "label": "Simple crank",
  "bodies": [{"id": "g"}, {"id": "input", "length": 35}],
  "joints": [{"id": "pivot", "type": "R", "a": "g", "b": "input", "pa": [10, 20], "pb": [0, 0]}],
  "driver": {"body": "input", "offset": 0},
  "output": {"body": "input", "point": [35, 0]},
  "seedPoses": {"input": [10, 20, 0]}
}
```

All lengths and positions are in millimetres and angles in radians. Ground body `g` is fixed at the world origin. Each other body has a pose `[x,y,angle]`. Joint local anchors `pa`/`pb` are defined in the frame of the respective bodies. `R` pins two coincident points. `P` additionally needs local `axisA` and `axisB` angles (default 0), constraining lateral motion and relative orientation while allowing one translational DOF. Driver is an absolute input-body angular position: `driver.offset + (driver.speed ?? 1) × input_angle`.

Custom graphs should include reasonable `seedPoses` or an initialization routine. A mobility count of one does not establish that a graph can assemble or traverse a full cycle. The importer supports user-defined one-DOF R/P graphs, but the **discovery generator** currently has the named seed primitives + dyad transformations only.

## Important modeling limitations

1. Ideal planar rigid bodies, frictionless and backlash-free joints; no forces, torque, masses, stress, dynamics, energy usage, clearance, self-collision, manufacturing tolerance, or physical fabrication geometry.
2. The solver tests discrete cycle phases (36 by default) with a branch-change heuristic; it can miss an issue between samples and does not prove continuous mobility, even if it reports a passing cycle.
3. A necessary graph mobility formula can fail for special or overconstrained geometries. Real assembly requires separate verification.
4. Candidate ranking uses geometrical RMSE plus an arbitrary **0.4 mm per extra moving body** complexity penalty, which is **not** a physical cost or proof of optimality. Different architecture types are not parameter-count matched.
5. A template-derived initial pose may serve as a recovery seed. The shared constraint solver nevertheless verifies positions and constraints and performs continuation/refinement. True fully arbitrary graph initialization remains unsolved.
6. JSON exports are editable research data. SVG is visual illustration, **not fabrication-ready CAD**.

## Next research milestones

1. Establish an externally held-out cross-topology benchmark suite of at least 25 target trajectories, multiple seeds, and objective feasibility metrics; benchmark against open-source mechanism synthesis systems.
2. Add independent collision and singularity/branch-continuity checks and explicit bounds on the mechanism workspace.
3. Model realistic loads, joint reactions, friction and input power; independently validate with another physics package.
4. Generate an assembly-aware dimensioned CAD file for one selected candidate, request mechanical-engineering review, then hand off only a physically checked device to hardware testing.
5. Search primary literature and patents before claiming originality of any **specific** proposed mechanism.
